JuicePlayer and Cues

The playback component, the preset-asset surface, and the code catalog — the API of the package.

JuicePlayer

JuicePlayer is the component that plays presets on its GameObject.

  • bool Play(string presetName) — plays a built-in catalog preset by name. Returns false for an unknown name and plays nothing; an unknown name never throws into your frame.
  • void PlayPreset(JuicePreset preset) and the looping overload PlayPreset(preset, bool loop) — plays a preset asset, optionally looping until stopped. Looping is how the Ambient & Idle shelf is used.
  • void StopAll(bool restore = true) — stops all cues on this player. Restoring cues write back the base values they captured, so a stopped effect never leaves a target squashed, tinted, or offset.
  • void Prewarm(JuicePreset preset) — rents and returns each channel's runners once, so the first real play of a known preset takes the pooled path as well.
  • int ActiveCueCount and bool IsPlaying — live playback state.
  • UnityEvent OnCueFinished — raised as each cue completes, exactly once per completed cue.

A play creates one cue: one context carrying the resolved Transform, SpriteRenderer, Graphic, and Rigidbody2D for the target, resolved once per play rather than per frame. Cues are pooled, and channel runners are pooled per channel type. Per-channel delays are honoured inside the cue: a channel with a delay does not move its target before the delay elapses, and its cue still completes and restores.

Preset assets of your own

JuicePreset is a ScriptableObject: a name, a shelf (category), a list of channels, an optional haptic pattern name, and a time mode — Scaled or Unscaled. TotalDuration is the longest channel end (delay + duration). Create one from Create > ByteLura > JuiceWorks Preset and author its channels in the preset inspector (Editor Preview & Inspectors). Your assets play through the same player, trigger, and sequencer surfaces as the built-ins.

The catalog in code

JuicePresetCatalog exposes the built-ins: Count, All, Find(name), and GetByCategory(category, results). Find of an unknown, empty, or null name returns null. JuiceGenrePacks exposes the three packs the same way.

Hit-stop, honestly

JuiceTime is the facade: RequestHitStop(duration, timeScale), CancelHitStop(), IsHitStopActive, and Current for tooling.

Overlapping hit-stops combine as longest remaining time and lowest time scale — never a multiplicative stack. When a stop ends, the time scale your game had before the stop began is restored. If the last JuiceWorks component is disabled mid-stop, the stop is cancelled immediately instead of leaving the game's time scale parked.

The driver

JuiceDriver is the hidden, self-creating ticker behind playback. You never place it. Players and sequencers register with it, and it removes itself when the last one unregisters. There is no manager object to add to a scene and no folder to create before the first preset plays.
