Troubleshooting and Support

Known symptoms, what causes them, and how to reach support.

A preset name plays nothing

Play returns false for an unknown name and plays nothing, by design — playback code does not throw into your frame. Check the spelling against the Preset Library: catalog names are exact and case-sensitive (HitMedium, not hitmedium). In code, JuicePresetCatalog.Find(name) returns null for an unknown, empty, or null name, which is the quickest check. A trigger with an empty preset name and no preset asset set also plays nothing.

Preview buttons are disabled in the window

Preview needs a target. Select a GameObject in the Hierarchy; the browser's empty-selection line — “Select a GameObject in the Hierarchy to preview presets on it.” — is replaced by active rows once something is selected.

A target is left squashed, tinted, or offset

Stopping or finishing a cue restores the base state the channels captured when the cue began, and Flash and Shake always restore. If a target stays changed, look for a channel authored in To mode with RestoreOnEnd off — scene exits and rising popups are authored that way on purpose and are named as such in the Preset Library. Your own preset assets can carry the same setting; it is a per-channel field in the inspector.

Hit-stop feels stacked or the time scale does not come back

Overlapping stops are designed to combine as longest remaining duration and lowest time scale, never as a multiplicative stack, and the pre-stop time scale is restored when the stop ends. If the time scale stays low, check whether another system in your project is also writing Time.timeScale. One designed exception to know: if the last JuiceWorks component is disabled mid-stop, the stop is cancelled immediately rather than leaving the time scale parked.

Haptics are silent

Work through the platform facts on the Haptics page:

  • In the Editor and on desktop, silence is correct — the no-op backend is active.
  • On iOS, expect exactly one system vibrate per pattern in this version; rhythm and amplitude are Android waveform features.
  • On any platform, check the master switch: with JuiceHaptics.Enabled off, no Play call reaches a backend.
  • An unknown pattern name is ignored without an error. Compare against the 12 built-in names on the Haptics page.
  • On Android, a pattern that cannot play as a waveform falls back to a timed vibrate, then to the system vibrate.

A sequence step never plays

Steps resolve presets by asset or by catalog name; an unresolvable step resolves to nothing rather than throwing, so a misspelled step name fails silently in the timeline. Check the step's name against the Preset Library, and check its Delay and WaitForPrevious values in the timeline inspector — a waiting step starts only after the previous step's preset finishes, plus its delay.

The sample scene reports a missing script

The sample ships scripts only, so every reference in the scene should be one you made during the build on the Sample Guide page. A missing-script message points at a step where a component was not added or a field was not assigned — rebuild the affected object following the Sample Guide step by step, in order.

Verify Install reports a failing check

Run Tools > ByteLura > JuiceWorks Pro / Verify Install again after re-importing the package. Each check prints one plain-language line stating what was checked; the failing line names the piece to fix — assembly, catalog, backend, or the engine self-test.
